# Intake and tailoring

## Writing profile fields

| Field | Why it matters | If missing |
| --- | --- | --- |
| Article type | Decides structure, length, reporting guideline | Ask; never guess |
| Venue name and type | Journal, conference, book chapter: scope, limits, review model | Ask; offer venue advice if undecided |
| Venue author guidelines | Word or page limit, section order, abstract type and length, keywords, figure limits, required statements | Ask for link or paste; otherwise flag every limit as unverified |
| Citation style | In-text format, list order, caption rules | From guidelines; else ask |
| Discipline and audience | Specialist or broad readership; conventions differ | Ask |
| Language variety | US or UK spelling and punctuation | Match the author's text |
| Voice and person | "We" is accepted in most sciences, discouraged in some fields | Follow venue; else match author |
| Author writing sample | Match rhythm, terms, hedging | Ask once; if declined, write neutral academic prose |
| Stage | Idea, outline, draft, revision, rebuttal | Infer; confirm |
| Help mode | Coach, edit, draft | Coach when unclear |
| Venue AI policy | What drafting is allowed, what must be disclosed | Ask; default to disclosure |

Precedence: venue instructions, then the style manual named by the venue, then discipline convention, then author preference, then skill default.

## Decision order for structure

1. **Venue template or user outline given:** follow exactly, including section names, order and limits.
2. **Partly given:** keep everything given; propose missing parts as clearly marked suggestions.
3. **Nothing given:** offer 2 or 3 structures typical for the field, article type and venue (see `article-types.md`), with one-line trade-offs; the user chooses.

## Function map

Every article performs these functions somewhere. Build a table mapping each to the user's section, or "missing".

| Function | Question answered |
| --- | --- |
| Problem and importance | What and why it matters, to whom |
| Positioning and gap | What is known, what is missing |
| Approach and justification | How, and why this way |
| Evidence or argument | What was found or shown |
| Interpretation | What it means against prior work |
| Contribution | What is new |
| Limits and implications | How far it holds, what follows |

## Warn versus accept: the deviation threshold

Warn once (then comply) when a choice threatens acceptance or integrity:

- A function is missing entirely (no gap statement, no method justification, no limitations, no comparison with prior work)
- Claims exceed the evidence (causal language for correlational data; generalisation beyond the sample)
- The structure contradicts a venue requirement (missing required statement, wrong abstract format, over the limit)
- A systematic-review claim without systematic methods
- Recommendations or implications not supported by the results

Accept silently as preference:

- Section names and ordering that still cover the functions
- Voice and person within venue rules
- Paragraph style, sentence rhythm, preferred terminology (if used consistently)
- Field-typical structure that differs from IMRaD
- Proportions between sections within venue limits

Record each warned decision and the user's answer so it is not reopened.

## Voice preservation

- Edits fix identified problems; they do not homogenise style.
- Do not rewrite a correct sentence because another phrasing is possible.
- Keep the author's terms unless they are inconsistent or wrong; then flag and propose one term.
- Non-native writing: prioritise correctness, clarity and consistency over sounding native.
